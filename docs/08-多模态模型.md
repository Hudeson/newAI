## 本章目标

1. 从零实现一个可训练的迷你 CLIP，理解对比学习为什么不需要任何分类标签；
2. 推导对称 InfoNCE 损失，并弄清 batch size 为什么直接决定表示质量；
3. 解剖对齐后的相似度结构，看清「零样本分类」到底是怎么发生的；
4. 遇到一个**诚实的负面观察**：模态鸿沟在这个规模下没有出现——
   并搞明白这意味着什么。

## 原理

### 对齐是多模态的第一步

多模态大模型（LLaVA、Qwen-VL 等）的通用配方是「视觉编码器 + 投影层 + LLM」，
而这套配方能成立的前提是视觉编码器输出的向量与语言空间**已经对齐**。
CLIP 做的就是这件对齐工作。

双塔结构，两个编码器各自把输入映射到同一个 $d$ 维空间并 L2 归一化：

$$
I_i = \frac{f_{\text{img}}(x_i)}{\|f_{\text{img}}(x_i)\|}, \qquad
T_j = \frac{f_{\text{txt}}(y_j)}{\|f_{\text{txt}}(y_j)\|}
$$

归一化之后内积就是余弦相似度，这让相似度有界、训练稳定。

### 对称 InfoNCE

一个 batch 里的 $N$ 个图文对，第 $i$ 个图像的正样本是第 $i$ 个文本，
**其余 $N-1$ 个文本都是负样本**。反过来也一样，于是损失是对称的：

$$
\mathcal{L} = \tfrac12\Big[\mathrm{CE}\big(\tau\, I T^\top,\ \mathrm{diag}\big)
            + \mathrm{CE}\big(\tau\, T I^\top,\ \mathrm{diag}\big)\Big]
$$

其中 $\tau$ 是可学习的温度（CLIP 里在对数空间参数化）。

两个要点：

1. **没有任何分类标签。** 监督信号完全来自「哪张图配哪段文字」这个配对关系，
   而配对在互联网上是免费的（图片 + alt text）。这是 CLIP 能扩到 4 亿对的根本原因；
2. **负样本数 = batch size − 1。** 对比任务的难度直接由 batch 决定，
   所以 CLIP 用了 32768 这种夸张的 batch size。实验 B 会量化这条。

### 零样本分类

对齐完成后，把每个类别名写成文本、编码成向量，然后看图像与哪个类别文本最近：

$$
\hat c = \arg\max_c\ I^\top T_c
$$

注意这里**没有训练任何分类头**。分类器是「类别名的文本嵌入」临时拼出来的，
所以换一套类别不需要重新训练——这就是「零样本」的含义。

## 代码导读

`dive/multimodal.py`：

```python
def l2_normalize(x, eps=1e-8) -> Tensor           # 让内积等于余弦相似度
class MiniCLIP(Module):
    image_proj:  Linear(image_dim -> embed_dim)   # 图像塔
    token_embed + text_proj                        # 文本塔：词嵌入 + 平均池化 + 投影
    log_temperature: Parameter                     # 可学习温度，对数空间
    def forward(images, token_ids) -> Tensor       # 对称 InfoNCE
@dataclass
class SyntheticImageText:                          # 原型 + 噪声的合成图文对
def train_clip(model, dataset, steps, batch_size, lr, ...) -> history
def zero_shot_classify(model, dataset, n) -> float
def retrieval_at_k(model, dataset, n, k) -> float
```

对称损失只有两行：

```python
logits = self.logits(images, token_ids)        # (N, N)，已乘温度
targets = np.arange(logits.shape[0])           # 对角线是正样本
return (cross_entropy(logits, targets) + cross_entropy(logits.transpose(), targets)) * 0.5
```

数据集是合成的：每个类别一个随机原型向量，「图像」= 原型 + 噪声，
「文本」= 类别名的字符 id 序列。这样既有可学的结构，又不需要下载任何数据。

**`train_clip` 里有一个必须注意的坑，代码里显式规避了：**

```python
# 一个 batch 内若出现同类别的重复文本，会构成「假负样本」——
# 同一个正确答案被当成负例去推远。这里按类别去重采样来规避。
labels = dataset.rng.permutation(n_classes)[:batch_size]
```

真实 CLIP 中每条 caption 都不相同，天然没有这个问题；但在类别名有限的
数据集上做对比学习，假负样本会实实在在地拖坏训练。这也解释了为什么
`batch_size = min(batch_size, n_classes)`——batch 不能超过类别数。

对应测试：`tests/test_multimodal.py`（`l2_normalize` 单位范数、
`MiniCLIP.logits` 的温度缩放、InfoNCE 性质、训练提升零样本准确率、
`retrieval_at_k` 的单调性）。

## 动手实验

```bash
python3 -m labs.lab08_multimodal              # 四个实验，约 2 秒
python3 -m labs.lab08_multimodal --noise 0.6  # 换数据可分性
python3 -m labs.lab08_multimodal --steps 800
```

数据：12 个类别，图像特征 24 维，噪声 0.35，文本词表 23（字符级，0 为 padding）。
**随机猜准确率 8.3%**。

### 实验 A：对比学习训练

| | |
| --- | --- |
| 训练前零样本准确率 | **6.8%**（≈ 随机猜 8.3%） |
| 训练后零样本准确率 | **76.8%** |
| 图搜文 R@1 | 81.0% |
| 图搜文 R@3 | **97.0%** |
| 学到的温度系数 | 12.10 |
| 训练用时 | 0.2s |

训练曲线：

```
step   1 | InfoNCE loss 4.9265 | 零样本准确率 15.0%
step 100 | InfoNCE loss 1.2966 | 零样本准确率 71.0%
step 200 | InfoNCE loss 0.6276 | 零样本准确率 81.0%
step 300 | InfoNCE loss 0.3441 | 零样本准确率 77.0%
step 400 | InfoNCE loss 0.9305 | 零样本准确率 79.0%
```

从 6.8%（随机水平）到 76.8%，**全程没有用过一个类别标签**。

留意 step 200 之后的现象：loss 还在往下走（0.63 → 0.34），
但零样本准确率不再提升（81% → 77%）。这是对比学习里常见的
「损失与下游指标脱钩」——loss 在优化 batch 内的区分度，
而零样本准确率考的是对全部 12 个类别的区分度，两者不是同一件事。
**实践含义：不要用对比损失当早停信号。**

### 实验 B：batch size 决定负样本数量

| batch size | 负样本数 | 零样本准确率 |
| --- | --- | --- |
| 2 | 1 | 66.8% |
| 4 | 3 | 72.2% |
| 8 | 7 | **76.8%** |
| 12 | 11 | 76.8% |

batch 越小，对比任务越简单（只要比 1 个负样本强就行），学到的表示也越粗糙。
这就是 CLIP 要用 32768 这种 batch size 的原因。

注意 8 → 12 已经饱和：本实验只有 12 个类别，batch=12 就是全部类别了，
再大也没有新的负样本可用。真实场景里「类别」是无穷的，所以 CLIP 的
batch size 收益一直延伸到很大的规模。

### 实验 C：解剖对齐后的相似度结构

| 相似度类型 | 余弦相似度 |
| --- | --- |
| 同类 图像-文本（配对） | **+0.545** |
| 同类 图像-图像 | +0.384 |
| 异类 图像-文本 | +0.032 |
| 异类 图像-图像 | −0.008 |

两个模态中心的距离：0.135。

读法：配对相似度（+0.55）远高于任何非配对组合（≤ +0.03），对齐是成功的。
值得注意的是，同类的「图像-文本」相似度反而**高于**同类的「图像-图像」——
文本向量成了该类别的一个**原型中心**，各张图像围绕它散开。
这正是零样本分类能工作的几何原因：类别名的文本嵌入天然是个好的类中心。

#### 一个诚实的说明

真实 CLIP 里存在明显的**模态鸿沟**（modality gap）：两个模态各自缩在超球面的
两个窄锥里，中心相距很远。但在这个规模下它**并没有出现**（模态中心距离仅 0.135）。

原因是这里的嵌入维度低（32 维）、两个塔的初始化对称、数据也很干净。
模态鸿沟主要是**高维空间中初始化与对比损失共同作用**的产物，
不是对比学习的必然结果。

这个负面结果值得留在文档里：**玩具实验能验证机制，但不能替代在真实规模上的观察。**
如果你只跑了这个实验就断言「模态鸿沟不存在」，那就错了；
反过来，如果因为看不到模态鸿沟就认为实现有 bug，也错了。

### 实验 D：数据可分性决定上限

| 噪声水平 | 零样本准确率 |
| --- | --- |
| 0.10 | **100.0%** |
| 0.25 | 93.8% |
| 0.50 | 54.2% |
| 0.80 | 30.5% |

噪声越大，图像原型本身就越难区分，再好的对齐算法也救不回来。
**多模态模型的能力边界，首先是数据质量的边界**——这也是为什么
LAION、DataComp 这类工作把大量精力放在数据清洗与过滤上。

## 思考题

1. 实验 A 中 loss 从 0.63 降到 0.34 时零样本准确率反而从 81% 掉到 77%。
   如果要选一个早停指标，你会选什么？为什么不能选 loss？
2. `log_temperature` 学到了 12.10（对应 $\tau^{-1} \approx 0.083$）。
   如果把它固定成 1.0 会怎样？固定成 100 呢？温度在 InfoNCE 里控制什么？
3. `train_clip` 按类别去重来避免假负样本。如果不去重，batch=12、类别=12 时
   平均会有多少个假负样本？（提示：这是一个生日问题。）
4. 文本塔用的是「词嵌入 + 平均池化」。换成一个 TinyLM（第 1 章）取最后一个
   位置的隐状态会更好吗？在这个字符级类别名任务上会有区别吗？
5. 实验 D 里噪声 0.1 能到 100%。这说明对比学习「解决」了这个任务吗？
   在什么意义上这个 100% 是不足信的？
6. 从这个迷你 CLIP 出发，要怎么接一个 LLM 变成 LLaVA？
   哪些部分需要训练，哪些可以冻住？（提示：LLaVA 的两阶段训练分别在训练什么？）
