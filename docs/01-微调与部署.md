## 本章目标

1. 搞清楚**指令微调（SFT）与预训练的唯一区别**：哪些位置参与损失；
2. 从零实现 LoRA，量化「可训练参数占比」与「效果」之间的关系；
3. 验证 LoRA 合并回主干后推理结果**逐位一致**，理解为什么它推理开销为零；
4. 把训练好的模型包成一个可交互的推理接口。

## 原理

### 自回归语言模型

一个 decoder-only 模型把序列的联合概率分解成逐 token 的条件概率：

$$
\log p_\theta(x_1,\dots,x_T) = \sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})
$$

训练目标就是最大化它，等价于最小化交叉熵：

$$
\mathcal{L} = -\frac{1}{|\mathcal{S}|}\sum_{t \in \mathcal{S}} \log p_\theta(x_t \mid x_{<t})
$$

**预训练与 SFT 的全部差别就在这个 $\mathcal{S}$ 上**：

- 预训练：$\mathcal{S}$ = 所有位置；
- SFT：$\mathcal{S}$ = 只有回答部分。提示词位置的标签被置为 `IGNORE_INDEX`（-100），
  既不产生损失也不产生梯度。

为什么要掩掉提示词？因为我们要教模型的是「给定这个问题，该怎么回答」，
而不是「怎么把这个问题本身编出来」。对提示词算损失会把训练信号浪费在
拟合输入分布上。

### LoRA：低秩适配

全参数微调要为每个下游任务存一份完整权重。一个 7B 模型 fp16 就是 14 GB，
十个任务 140 GB。LoRA 的观察是：微调带来的权重改动 $\Delta W$ 往往是**低秩**的，
于是可以只学它的低秩分解：

$$
h = xW + \frac{\alpha}{r}\,(xA)B,\qquad A \in \mathbb{R}^{d_{in}\times r},\; B \in \mathbb{R}^{r \times d_{out}}
$$

其中 $r \ll \min(d_{in}, d_{out})$，$W$ 全程冻结。两个关键设计：

- **$B$ 初始化为 0**，因此训练开始的瞬间 $\Delta W = AB = 0$，模型输出与原模型
  **完全一致**。这保证微调是一个「从原模型出发」的连续过程，而不是随机扰动；
- **$\alpha/r$ 缩放**，让改变 $r$ 时不必重调学习率。

训练完成后可以合并：$W' \leftarrow W + \frac{\alpha}{r}AB$。这是精确的代数恒等式，
合并后推理路径与原模型一模一样，**没有任何额外算子、额外延迟**。

参数量对比：原层 $d_{in}\times d_{out}$，适配器 $r(d_{in}+d_{out})$。
取 $d=4096, r=8$，比例是 $\frac{8\times 8192}{4096^2} \approx 0.39\%$。

## 代码导读

### 模型：`dive/transformer.py`

`TinyLM` 是 LLaMA 风格的 decoder-only 模型，结构与主流开源模型一致，只是很小：

| 组件 | 实现 | 说明 |
| --- | --- | --- |
| Pre-Norm + RMSNorm | `dive/nn.py::RMSNorm` | 比 LayerNorm 少一个均值项，省一次归约 |
| RoPE | `transformer.py::rope_tables` / `apply_rope` | 旋转位置编码，无可学习位置参数 |
| 因果自注意力 | `CausalSelfAttention` | 支持 KV Cache 增量解码 |
| SwiGLU | `SwiGLU` | `w2(silu(w1 x) * w3 x)`，隐层宽度按 LLaMA 规则取 `8/3·dim` 对齐到 8 |
| 权重共享 | `TinyLMConfig.tie_embeddings` | 输出头复用词嵌入矩阵 |

值得注意的一处：`CausalSelfAttention.forward` 里的因果掩码按**绝对位置**计算，

```python
query_pos = np.arange(total - seq, total)[:, None]
key_pos = np.arange(total)[None, :]
mask = key_pos > query_pos
```

这样它对「一次喂 T 个 token」和「带 cache 逐个喂」两种情况都正确。
`tests/test_transformer.py::test_kv_cache_matches_full_forward` 验证了两者
逐位偏差 < 1e-12。

### 训练：`dive/training.py`

核心是两个 batch 构造函数，差别只有一行掩码：

```python
def causal_batch(sequences, pad_id):        # 预训练：每个 token 都算损失
    ...
    targets[positions >= (lengths[:, None] - 1)] = IGNORE_INDEX   # 只掩 padding

def sft_batch(sequences, prompt_lengths, pad_id):   # SFT：只算回答部分
    inputs, targets = causal_batch(sequences, pad_id)
    targets = np.where(positions < prompt_len - 1, IGNORE_INDEX, targets)
```

`prompt_len - 1` 这个 off-by-one 很容易写错：`targets[t]` 预测的是原序列第
`t+1` 个 token，所以「回答的第一个 token」落在 `t = prompt_len - 1` 上，它**必须**
参与损失。`tests/test_training.py::test_sft_batch_masks_exactly_the_prompt_positions`
把这条边界钉死了。

`train_causal_lm` 是标准循环：AdamW + 梯度裁剪 + 每 epoch 打印损失与困惑度。

### LoRA：`dive/lora.py`

```python
class LoRALinear(Module):
    def __init__(self, base: Linear, rank=4, alpha=None, rng=None):
        freeze(base)                                    # 冻结基座
        self.lora_a = Parameter(rng.normal(...))         # 小随机数
        self.lora_b = Parameter(np.zeros((rank, out)))   # 零初始化

    def forward(self, x):
        return self.base(x) + ((x @ self.lora_a) @ self.lora_b) * self.scaling

    def merge(self) -> Linear:
        self.base.weight.data = self.base.weight.data + self.delta()
        self.lora_b.data = np.zeros_like(self.lora_b.data)
        return self.base
```

`apply_lora(model, rank, targets=("wq", "wv"))` 遍历 `named_modules()`，把命中
名字的 `Linear` 原地换成 `LoRALinear`。默认只适配 `wq`/`wv` —— 这是 LoRA 论文中
性价比最高的配置。`lora_state_dict` 只导出适配器，这正是「一个基座 + 一堆几 MB
小文件」的由来。

### 任务：`labs/_tasks.py`

情感分类任务的测试集刻意由**训练中从未共现的「主语 + 情感词」组合**构成
（如「这本书 + 惊艳」在训练里从未同时出现）。因此测试准确率反映的是组合泛化，
而不是背题。

### 实测结果

任务概览：63 条训练样本 / 9 条测试样本，字符表 43，模型 3 层 96 维，
共 **336,576** 参数。首个 batch 形状 `(32, 18)` 共 576 个位置，其中**只有 96 个
参与损失**，其余全被 `IGNORE_INDEX` 掩掉 —— 这就是 SFT 与预训练的全部差别。

| 方案 | 可训练参数 | 占比 | 训练末期 loss | 测试准确率（组合泛化） |
| --- | --- | --- | --- | --- |
| 全参数微调 | 336,576 | 100% | 0.0007 | **100.0%** |
| LoRA r=8 | 9,216 | **2.67%** | 1.8827 | **100.0%** |

微调前的测试准确率是 **0.0%**（随机初始化的模型根本不会输出「正面 / 负面」）。

合并验证：

```
被替换的线性层          : layers.{0,1,2}.attn.{wq,wv}
合并的 LoRA 层数        : 6
合并前后 logits 最大偏差 : 1.33e-15（数值误差量级）
合并后测试准确率        : 100.0%
```

1.33e-15 是 float64 的机器精度量级（$\varepsilon \approx 2.2\times10^{-16}$），
说明合并是**精确**的，不是「近似不变」。

部署段会打印 5 条测试样例的预测，全部命中：

```
✓ 评论:这本书真的惊艳 | 情感:正面   (标准答案 正面)
✓ 评论:这家餐厅特别乏味 | 情感:负面   (标准答案 负面)
```

### 读法

- 2.67% 的可训练参数拿到了与全参数微调**相同**的准确率，适配器只有 72 KB
  （完整权重是 2.6 MB）。真实场景里这个比例决定了「一台机器能同时服务多少个
  定制模型」；
- **最值得盯的是 loss 那一列**：全参微调把损失压到 0.0007（几乎完全记住了
  训练集），LoRA 停在 1.88，差了三个数量级 —— 但两者的任务准确率都是 100%。
  原因是这个任务只要求 argmax 正确，而 LoRA 受低秩约束无法记住每条样本的
  完整分布。这正是「LoRA 是一种正则化」这个说法的直观来源：它拟合能力更弱，
  却不影响任务表现，甚至更不容易过拟合；
- 合并后 6 个 `LoRALinear` 变回普通 `Linear`，推理图与原模型完全相同，
  额外延迟为零。

## 思考题

1. 把 `apply_lora` 的 `targets` 从 `("wq", "wv")` 改成 `("wq", "wk", "wv", "wo")`
   或只改 `("w1", "w2", "w3")`（FFN），可训练参数与准确率各变化多少？
   LoRA 论文的结论（同等预算下适配 `wq`/`wv` 优于只适配一个矩阵）能复现吗？
2. `lora_b` 如果也用小随机数初始化会发生什么？动手改一下，观察训练前几个 epoch
   的损失曲线，并解释为什么原论文坚持零初始化。
3. `sft_batch` 里把 `prompt_len - 1` 写成 `prompt_len`，准确率会怎么变？
   为什么这个 bug 很难在损失曲线上被发现？（提示：跑
   `pytest tests/test_training.py -k sft_batch`）
4. 本章的测试集是「组合泛化」型的。如果改成随机划分（测试组合在训练中出现过），
   两种方案的准确率会怎么变？这说明了什么关于「评测集设计」的事？
5. 情感分类只需要生成 2 个字符。如果任务变成生成一段长文本，
   LoRA 与全参微调的差距会变大还是变小？为什么？
