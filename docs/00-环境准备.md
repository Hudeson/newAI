# 第 0 章 · 环境准备

> 本仓库是《动手学大模型 Dive into LLMs》课程大纲的一份**独立实现**，
> 上游教程见 [Lordog/dive-into-llms](https://github.com/Lordog/dive-into-llms)（上海交通大学 张倬胜 老师团队）。
> 本仓库不复制上游任何内容，所有代码与文字均为原创。

## 本章目标

- 在一台**没有 GPU、没有联网**的机器上跑通全部 11 章实验；
- 理解本仓库为什么用纯 NumPy 而不是 PyTorch；
- 知道如何把这些实验迁移到真实开源大模型上（可选进阶）。

## 一、最小环境（推荐，5 分钟）

只需要 Python 3.10+ 与 NumPy：

```bash
python3 --version          # 需要 >= 3.10（用到了 X | Y 类型标注）
python3 -m pip install numpy pytest
```

验证环境：

```bash
git clone <本仓库地址> && cd <仓库目录>
python3 -m pytest              # 291 个用例，约 2.5 秒
python3 -m labs.lab09_gui_agent   # 最快的一个实验，1 秒内出结果
```

仓库运行时的**唯一依赖是 NumPy**，`pytest` 只在跑测试时需要。没有 PyTorch、
没有 transformers、不下载任何权重、不访问网络。

如果你习惯用 conda：

```bash
conda create -n dive-numpy python=3.11 numpy pytest -y
conda activate dive-numpy
```

国内网络下 pip 走清华镜像会快很多：

```bash
python3 -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple numpy pytest
```

## 二、为什么是纯 NumPy

大模型课程最常见的两个卡点，都跟大模型本身无关：**装不上环境**、**跑不动模型**。
本仓库的选择是把这两个问题彻底移除，代价是模型规模很小（几万到几十万参数）。

这个取舍能成立，是因为本课程要讲的绝大多数结论**与规模无关**：

| 结论 | 需要多大的模型才能看到 |
| --- | --- |
| LoRA 合并回主干后推理结果逐位一致 | 任意规模，这是代数恒等式 |
| SFT 只对回答部分算损失 | 任意规模，这是 batch 构造 |
| 把推理过程写出来能提升准确率 | 一个 3 层的迷你模型就能复现（第 2、4 章） |
| 水印藏在熵里，低熵文本打不上水印 | 任意规模，这是信息论约束 |
| 隐写的嵌入率上限等于模型每步的熵 | 任意规模，这是 Huffman 编码的性质 |
| ROME 的 `C⁻¹` 项决定副作用大小 | 一个线性关联记忆就能复现（第 3 章） |
| PPO 的 KL 惩罚必须扣在奖励上 | 任意规模，放错位置一定崩（第 11 章） |
| 智能体护栏必须在工具执行前生效 | 与模型无关，是运行时设计 |

而**确实需要大规模才能观察**的现象，本仓库会明确写出来，不假装能复现。
例如第 8 章的「模态鸿沟」在本仓库的规模下并未出现，实验输出里对此有专门说明。

另一个好处是：整个计算栈都是可读的。`dive/autograd.py` 一共 400 多行，
包含了反向传播的全部机制。当你想知道「RMSNorm 的梯度到底是什么」时，
可以直接读代码，而不是读一个 C++ kernel 的签名。

## 三、目录与运行方式

```
dive/       核心库（纯 NumPy）：自动微分、Transformer、LoRA、水印、对齐、智能体……
labs/       11 个可运行的实验脚本，每章一个
docs/       本教程（你正在读的这部分）
tests/      291 个 pytest 用例
```

所有实验都以模块方式运行，**必须在仓库根目录执行**（否则 `import dive` 找不到）：

```bash
python3 -m labs.lab01_finetune            # 正确
python3 labs/lab01_finetune.py            # 错误：相对导入会失败
```

每个实验都支持 `--help` 查看可调参数：

```bash
python3 -m labs.lab05_watermark --help
```

## 四、硬件预期与实测耗时

以下耗时实测于一台 **4 核 CPU / 15 GB 内存、无 GPU** 的容器（Python 3.12、NumPy 2.4）。
没有任何一步需要显存。

| 实验 | 命令 | 实测耗时 |
| --- | --- | --- |
| 第 1 章 微调与部署 | `python3 -m labs.lab01_finetune` | ~15 秒 |
| 第 2 章 提示学习与思维链 | `python3 -m labs.lab02_prompting_cot` | 2 分 45 秒（`--quick` 36 秒） |
| 第 3 章 知识编辑 | `python3 -m labs.lab03_knowledge_edit` | < 1 秒 |
| 第 4 章 数学推理 | `python3 -m labs.lab04_math_reasoning` | **8 分 21 秒**（`--quick` 约 1 分钟） |
| 第 5 章 模型水印 | `python3 -m labs.lab05_watermark` | 1 分 27 秒 |
| 第 6 章 越狱攻击 | `python3 -m labs.lab06_jailbreak` | 19 秒 |
| 第 7 章 大模型隐写 | `python3 -m labs.lab07_stega` | 19 秒 |
| 第 8 章 多模态模型 | `python3 -m labs.lab08_multimodal` | 2 秒 |
| 第 9 章 GUI 智能体 | `python3 -m labs.lab09_gui_agent` | < 1 秒 |
| 第 10 章 智能体安全 | `python3 -m labs.lab10_agent_safety` | < 1 秒 |
| 第 11 章 RLHF 安全对齐 | `python3 -m labs.lab11_rlhf` | 17 秒 |
| 全部测试 | `python3 -m pytest` | 2.4 秒（291 passed） |

第 4 章明显最慢，因为它的思维链目标序列长达 33 个字符，且要训练
三个模型加四个蒸馏规模。它也是全仓库对比最强烈的一组结果（0% vs 92.5%），
值得花这 8 分钟。

想一次跑完全部实验：

```bash
bash run_all_labs.sh          # 快速集合（第 2、4 章走 --quick），约 4 分钟
bash run_all_labs.sh --all    # 完整版，约 14 分钟
bash run_all_labs.sh --log out/    # 顺便把每章输出存进 out/
```

**一个内存方面的实测提醒**：第 4 章完整版在 15 GB 内存的机器上单独跑没问题，
但若与另一个实验并行运行，曾被 OOM killer 杀掉。`run_all_labs.sh`
是**串行**执行的，请不要手工并行跑多个实验。

所有实验都固定了随机种子，**同一台机器上重复运行结果完全一致**；
换机器时浮点尾数可能有微小差异，但所有结论级别的数字不会变。

## 五、可选进阶：把实验搬到真实模型上

本仓库的抽象刻意与主流框架对齐，因此每章实验都能换成真实模型。下面是迁移要点。

### 5.1 装 PyTorch + transformers

```bash
python3 -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple \
    torch transformers datasets accelerate peft
```

CPU 环境下建议装 CPU 版 torch（体积小很多）：

```bash
python3 -m pip install torch --index-url https://download.pytorch.org/whl/cpu
```

### 5.2 从镜像站下载权重

HuggingFace 直连不稳时，用 [hf-mirror](https://hf-mirror.com)：

```bash
export HF_ENDPOINT=https://hf-mirror.com
python3 -m pip install -U huggingface_hub
huggingface-cli download Qwen/Qwen2.5-0.5B-Instruct --local-dir ./qwen2.5-0.5b
```

`Qwen2.5-0.5B-Instruct`、`TinyLlama-1.1B`、`Qwen2.5-1.5B-Instruct` 这几个量级
在纯 CPU 上做推理是可行的（每秒几个 token），做 LoRA 微调也勉强能跑。

### 5.3 各章的对应关系

| 本仓库 | 真实技术栈 |
| --- | --- |
| `dive.transformer.TinyLM` | `transformers.AutoModelForCausalLM` |
| `dive.training.sft_batch` | TRL 的 `SFTTrainer`（`DataCollatorForCompletionOnlyLM`） |
| `dive.lora.apply_lora` | `peft.LoraConfig` + `get_peft_model` |
| `dive.decoding.generate` | `model.generate(...)` |
| `dive.decoding.LogitsProcessor` | `transformers.LogitsProcessor` |
| `dive.watermark.GreenListWatermark` | 官方实现 [jwkirchenbauer/lm-watermarking](https://github.com/jwkirchenbauer/lm-watermarking) |
| `dive.knowledge_edit.rome_edit` | [EasyEdit](https://github.com/zjunlp/EasyEdit) |
| `dive.rlhf.train_dpo` / `ppo_train` | `trl` 的 `DPOTrainer` / `PPOTrainer` |
| `dive.agent.ReActAgent` | LangChain / LlamaIndex 的 Agent 运行时 |
| `dive.multimodal.MiniCLIP` | `open_clip` / `transformers.CLIPModel` |

### 5.4 不想训练，只想调 API

`dive.prompting.OpenAICompatClient` 只用标准库实现了 OpenAI 兼容接口，
可直接对接 DeepSeek、Kimi、vLLM、Ollama 等服务，用来做第 2 章的提示工程实验：

```python
from dive.prompting import OpenAICompatClient, chain_of_thought_prompt

client = OpenAICompatClient(
    base_url="http://localhost:11434/v1", api_key="ollama", model="qwen2.5:7b"
)
print(client.complete(chain_of_thought_prompt("一个笼子里有鸡和兔共 35 只，脚共 94 只，各几只？")))
```

## 六、常见问题

**`ModuleNotFoundError: No module named 'dive'`**
说明不在仓库根目录。`cd` 到含 `dive/` 的目录再运行，或 `export PYTHONPATH=$PWD`。

**`python3 -m venv` 报 `ensurepip is not available`**
部分精简发行版没装 `python3-venv`。要么 `apt install python3-venv`，
要么直接用系统 Python（本仓库依赖极少，污染风险很低），
要么 `pip install --break-system-packages numpy pytest`。

**实验跑得比表格里慢**
NumPy 的矩阵乘会用满所有核心。若机器上有别的负载，或 NumPy 没链接到 BLAS
（`python3 -c "import numpy; numpy.show_config()"` 可以查看），耗时会明显变长。
先试 `--quick`（第 2、4 章支持）。

**改了 `dive/` 里的代码，实验结果变了**
先跑 `python3 -m pytest`。291 个用例覆盖了每个算子的梯度、KV Cache 的一致性、
LoRA 合并的精确性等，绝大多数改动带来的问题会立刻被它抓住。
