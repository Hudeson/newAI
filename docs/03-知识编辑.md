## 本章目标

1. 理解「FFN 是线性关联记忆」这个视角，以及它为什么让改一条事实变成解一个方程；
2. 推导并实现 ROME 的闭式秩一更新；
3. 学会用**有效性（efficacy）+ 局部性（locality）**两个指标评价编辑，
   而不是只看「改对了没有」；
4. 亲眼看到「只看有效性」会漏掉什么：连续编辑时知识库如何崩塌。

## 原理

### 把 FFN 看成关联记忆

Transformer 的 FFN 是 $\mathrm{FFN}(x) = W_{down}\,\sigma(W_{up}x)$。
把 $k = \sigma(W_{up}x)$ 看作**键**、$v = W_{down}k$ 看作**值**，
那么 $W_{down}$ 就是一个线性关联记忆：它把「主语的表示」映射到「客体的表示」。

这个视角来自 Geva 等人对 FFN 的分析，也是 ROME 的出发点。本章把它抽象成
`AssociativeMemory`：一个矩阵 $W \in \mathbb{R}^{d_k \times d_v}$，
$\mathrm{recall}(k) = k^\top W$。

### ROME 的秩一更新

要让新事实 $k^* \mapsto v^*$ 成立，同时尽量不动其他知识，可以写成一个带约束的
最小二乘问题：

$$
\min_{\hat W} \; \|\hat W - W\|_{C}^2 \quad \text{s.t.} \quad \hat W^\top k^* = v^*
$$

其中范数由键的二阶矩 $C = \mathbb{E}[kk^\top]$ 加权。它有闭式解：

$$
\hat W = W + \frac{(v^* - W^\top k^*)\,(C^{-1}k^*)^\top}{(C^{-1}k^*)^\top k^*}
$$

三点值得注意：

1. **更新是秩一的**：$\Delta W$ 是两个向量的外积，秩恒为 1。
   `tests/test_knowledge_edit.py::test_rome_edit_is_effective_and_rank_one` 验证了这点；
2. **约束精确满足**：代入即得 $\hat W^\top k^* = v^*$，所以有效性总是 1.000。
   这也意味着「有效性」这个指标区分不出好坏方法；
3. **$C^{-1}$ 决定副作用**。若取 $C = I$，更新方向就是 $k^*$ 本身，即最小 L2 改动。
   但真实模型里不同主语的表示**远非正交**（它们共享大量语言结构），
   沿 $k^*$ 方向改动会顺带拖动所有与 $k^*$ 相关的键。乘上 $C^{-1}$ 相当于
   先把空间「白化」，把改动推到与其他键尽可能正交的方向上。

### 评价指标

| 指标 | 含义 | 只看它会怎样 |
| --- | --- | --- |
| 有效性 efficacy | 新事实召回的相似度 | 所有闭式方法都是 1.000，毫无区分度 |
| 局部性 locality | 其他事实召回向量的平均相似度 | 这里才能看出方法差异 |
| max_drift | 被伤得最重的那条知识的相对偏移 | 平均值会掩盖个别灾难 |
| rank(ΔW) | 权重改动的秩 | 检查实现是否真的是秩一更新 |

## 代码导读

`dive/knowledge_edit.py` 只有四个部件：

```python
class AssociativeMemory:            # v = k^T W，外加 fit()（岭回归「预训练」）
def rome_edit(memory, key, value, covariance=None, ridge=1e-4)
def finetune_edit(memory, key, value, steps=200, lr=0.1)   # 对照组
def evaluate_edit(before, after, edit_key, edit_value, other_keys) -> EditReport
```

`rome_edit` 的核心就是上面那个公式：

```python
if covariance is None:
    direction = key                      # 退化为最小 L2 改动
else:
    cov = cov + ridge * np.trace(cov) / cov.shape[0] * np.eye(cov.shape[0])
    direction = np.linalg.solve(cov, key)     # C^{-1} k*
denom = float(direction @ key)
residual = value - memory.recall(key)
delta = np.outer(direction / denom, residual)
```

`FactStore` 把「文字事实」映射成向量记忆，让实验读起来像真的知识库：

```python
store = FactStore(dim=20, seed=0, correlation=0.9)
store.add_many([("埃菲尔铁塔位于", "巴黎"), ("故宫位于", "北京"), ...])
memory = store.fit()
store.recall("埃菲尔铁塔位于")     # -> '巴黎'
```

**`correlation` 是本章最关键的旋钮。** 它控制主语向量之间的相关性：
取 0 时各主语正交，改一条事实不会牵连别的，ROME 的 $C^{-1}$ 项也就失去意义
（`tests/test_knowledge_edit.py::test_zero_correlation_makes_covariance_irrelevant`
把这个退化情形固定了下来）。真实模型对应的是高相关的情形，所以实验默认 0.9。

| ROME（带协方差） | 威尼斯 | 1.000 | **1.000** | 100% | 7.30 |
| ROME（单位协方差） | 威尼斯 | 1.000 | 0.727 | 100% | 1.12 |
| 朴素梯度微调 | 威尼斯 | 1.000 | 0.727 | 100% | 1.12 |

| --- | --- | --- |
| 0 | 100% | 100% |
| 1 | 100% | 74% |
| 2 | 100% | 94% |
| 3 | 100% | **35%** |
| 4 | 100% | 56% |
| 5 | 100% | 80% |
| 6 | 100% | 100% |
| 7 | 100% | 92% |
| 8 | 100% | 100% |

### 读法

这张表里有四件值得停下来想的事：

1. **有效性完全没有区分度**。三种方法都是 1.000，因为它们都精确满足了约束。
   任何只报告 efficacy 的知识编辑评测都是没有信息量的；
2. **局部性是先行指标，准确率是滞后指标**。单次编辑后三种方法的「其他事实准确率」
   都还是 100%，但局部性已经从 1.000 掉到 0.727 —— 表示已经被推偏了，
   只是还没偏到让最近邻判断翻车。连续编辑几次之后，这笔账就一次性结清了；
3. **朴素梯度微调与「单位协方差 ROME」结果逐位相同**（局部性、‖ΔW‖ 都一样）。
   这不是巧合：对单个样本做梯度下降收敛到的正是最小 L2 改动解。
   换句话说，ROME 相对朴素微调的**全部价值都在 $C^{-1}$ 这一项上**；
4. **带协方差的 ‖ΔW‖ 反而更大**（7.30 vs 1.12）。它宁愿多改一点，
   也要把改动放在与其他键正交的方向上。这告诉我们「改动小」不等于「副作用小」，
   用改动范数当代理指标是错的。

单位协方差版本的准确率曲线是**非单调**的（74% → 94% → 35% → 56% → …）。
这不是噪声：每次编辑都在把若干条知识推过或推回最近邻的决策边界，
所以有的编辑会「意外修好」之前被破坏的事实。真实模型上的连续编辑也有类似现象，
这也是为什么评价连续编辑必须看整条曲线而不是最后一个数。

### 一个必要的免责声明

实验里的协方差是从**全部**键精确算出来的，记忆也严格线性，
所以带协方差 ROME 的 100% 是**理想上界**。真实模型里：

- $C$ 只能从语料抽样估计，有误差；
- FFN 之外还有注意力与非线性，一条事实并不只存在一个矩阵里；
- 连续编辑到几百上千条时同样会崩。

这正是 MEMIT 等后续方法要**一次性联立求解所有事实**、而不是逐条叠加的原因。

## 思考题

1. 跑 `--correlation 0.0`，两种 ROME 的局部性会怎样？为什么这时 $C^{-1}$ 失效了？
   这对「在真实模型上估计 $C$ 要用多少语料」有什么启示？
2. `rome_edit` 里的 `ridge` 项（`cov + ridge·tr(C)/d·I`）去掉会怎样？
   什么情况下 $C$ 是奇异的？
3. 把 `--sequential` 调到 15、20，带协方差的 ROME 还能保持 100% 吗？
   在什么条件下它一定会失败？（提示：秩一更新叠加 $n$ 次，$\Delta W$ 的秩最多是多少？
   当 $n$ 接近 $d_k$ 时会发生什么？）
4. 本章的「客体向量」是随机的正交方向。如果两个客体本身很相似
   （比如「巴黎」和「里昂」），编辑的难度会怎么变？
5. 知识编辑与第 1 章的 LoRA 都在「小幅修改一个已训练好的模型」。
   两者的目标函数差别在哪？为什么知识编辑要求闭式解而微调不要求？
