# 旺店通旗舰版 · 订单导入操作手册

> 适用产品：慧策旺店通 ERP **旗舰版**（客户端建议 V1.5.9.9 及以上）  
> 文档版本：1.0  
> 编制日期：2026-09-05  
> 适用岗位：客服、运营、仓配、实施、对接开发

本手册说明如何把外部订单导入旗舰版，并完成「原始订单 → 系统订单 → 审核发货」的标准流转。菜单路径以旗舰版客户端为准；不同小版本文案可能略有差异，以当前界面为准。

接口字段与限制以慧策开放平台旗舰版文档为准：  
[https://open.wangdian.cn/qjb/open/apidoc](https://open.wangdian.cn/qjb/open/apidoc)

---

## 1. 导入方式怎么选

旗舰版把「平台抓来的单 / 手工录的单 / 接口推进来的单」都先落到 **原始订单**，再递交生成系统订单。只有「已完成订单导入」是补历史单，不走待发货履约。

| 场景 | 推荐方式 | 客户端路径 | 结果落点 |
| --- | --- | --- | --- |
| 淘宝 / 京东 / 拼多多 / 抖音等已授权店铺 | 平台自动抓单 | 销售 → 订单管理 → 原始订单 | 原始订单 |
| 线下单、电话单、微信单，每天几十单以内 | 手工建单 | 销售 → 新增订单 / 手工建单 | 待审核系统订单 |
| Excel / CSV 批量补录、活动团购、外部系统导出 | 文件导入 | 销售 → 新增订单 → 订单导入 | 原始订单或订单导入列表 |
| 自研商城、分销、全渠道系统实时推单 | 原始单推送接口 | `sales.RawTrade.pushSelf2` | 销售 → 订单管理 → 原始订单 |
| 财务 / SAP / 线下 ERP 补已发货历史单 | 已完成订单推送 | `sales.TradeImport.upload` | 销售 → 新增订单 → 订单导入（待转已完成） |

选择原则：

1. 能授权抓单的平台，不要手工导入，避免重复单号和漏发。
2. 需要后续审单、打单、出库的，走 **原始单**（手工 / 文件 / `pushSelf2`）。
3. 已经在外部系统发完货、只补旗舰版台账的，走 **已完成订单导入**。
4. `sales.RawTrade.pushSelf` 已过时，新对接一律用 `sales.RawTrade.pushSelf2`。

## 2. 导入前必须完成的准备

缺任一基础档案，导入都会失败或卡在递交异常。

### 2.1 账号与权限

登录旗舰版客户端或 Web 端。操作账号至少具备：

- 店铺查看 / 使用权限（接口推单还要对应店铺权限）
- 仓库查看 / 使用权限
- 销售 → 原始订单、新增订单、订单审核
- 货品档案查询

接口对接还需在开放平台申请 `sid`、`key`（appkey）、`appsecret`（`secret:salt`）。

### 2.2 店铺

路径：**设置 → 基本设置 → 店铺**

| 检查项 | 要求 |
| --- | --- |
| 店铺编号 `shop_no` | 唯一、未停用；接口推单必须用这个编号 |
| 店铺名称 | 文件导入按名称匹配，必须与模板完全一致 |
| 店铺平台 | 接口推自有商城订单时，平台类型须为「自有 / 其它」 |
| 授权状态 | 平台抓单店铺须授权成功；失败则在店铺列表重新授权 |

线下单、手工导入不要借用淘宝 / 京东等线上店铺。单独建一个「线下店」「自有商城」店铺，避免和平台抓单混在一起。

京东等平台店铺通常只能推线上单据到三方仓。手工建单请使用单独创建的线下 / 自有店铺。

### 2.3 仓库与物流

路径：**设置 → 基本设置 → 仓库**、**设置 → 基本设置 → 物流**

- 仓库编号、仓库名称未停用。
- 文件导入按仓库名称匹配；接口可传 `warehouse_no`。
- 物流公司名称必须与系统档案一致（例如「中通快递」，不要写成「中通」）。
- 选仓策略、物流策略已配置，否则递交后可能进异常单。

### 2.4 货品与平台货品匹配

路径：**货品 → 货品档案**、**货品 → 平台货品**

导入认的是 **商家编码（规格编码 / `spec_no`）**，不是货品名称。

| 编码 | 含义 | 导入时 |
| --- | --- | --- |
| 货品编码 `goods_no` | SPU | 建议填写，不能与规格编码同时为空 |
| 商家编码 `spec_no` / `merchant_no` | SKU，系统匹配主键 | **必填，且必须已存在于货品档案** |
| 组合装编码 | 组合装档案中的编码 | 组合装订单填组合装编码，不要拆成子件 |

平台抓单还要在「平台货品」里完成平台 SKU 与系统商家编码的匹配，否则原始单递交会报「货品未匹配」。

### 2.5 单号规则

| 单号 | 说明 |
| --- | --- |
| 原始单号 `tid` | 平台 / 外部系统订单号。同一卖家账号 `sid` 下必须唯一 |
| 原始子单号 `oid` | 一笔订单里每个货品行一条。建议 `{tid}-{行号}` |
| 系统订单号 `trade_no` | 旗舰版递交后自动生成；已完成订单导入时由调用方提供且不可重复 |

手工单建议：`2 位字母前缀 + 年月日 + 流水号`，例如 `XX202609050001`。不要使用平台真实单号去导线下单。

## 3. 平台自动抓单（优先使用）

已授权的电商平台订单，由旗舰版定时拉取，一般无需导入。

1. **设置 → 基本设置 → 店铺** 确认授权有效、抓单开关开启。
2. **销售 → 订单管理 → 原始订单** 按店铺、下单时间、平台状态筛选。
3. 新单状态多为「未确认 / 待发货」。货品已匹配的，可自动或手动 **递交**。
4. 递交成功后进入 **销售 → 订单审核**，按策略选仓、选物流后审核。

抓单失败常见原因：店铺授权过期、平台限流、平台货品未匹配、收件信息被平台脱敏。先在原始订单看失败原因，再决定是否改用手工 / 文件补单。

同一平台单号禁止再通过 Excel 或接口导入，系统会判重复。

## 4. Excel / CSV 批量导入

适合一次性补录、团购表、外部 ERP 导出。客户端路径：**销售 → 新增订单 → 订单导入**。部分版本也在 **销售 → 订单管理 → 原始订单** 提供「导入」。

### 4.1 操作步骤

1. 进入 **订单导入**，点击 **下载模板**。以当前客户端下载的官方模板为准，不要沿用旧表头。
2. 用本手册 `templates/订单导入模板.csv` 对照填写。Excel 请另存为 `.xlsx` 或 `CSV UTF-8`。
3. 删除示例行，从第 2 行开始放真实数据。一笔订单多个货品：多行、**原始单号相同**、子单号不同。
4. 点击 **导入 / 上传**，选择文件。
5. 按提示选择编码（中文环境一般选 UTF-8；若乱码改 GBK / GB2312）。
6. 核对字段映射。表头与模板不一致时，手动把列映射到系统字段。
7. 预览：看新增 / 更新条数、必填是否为空、商家编码是否识别。
8. 确认导入。记录成功数、失败数，下载错误报告。
9. 到 **原始订单** 按原始单号查询，检查收件人、货品、金额。
10. 选中订单 **递交**（或等待自动递交），再到 **订单审核** 处理。

### 4.2 填写规则

- 同一原始单号的收件人、地址、店铺、下单时间必须完全一致，系统按原始单号合并主单。
- 邮费、优惠只在该原始单号的 **第一行** 填写，其余行留空，避免邮费被加多次。
- 数量必须大于 0；单价、应收不要留文本（如「免费」「待定」）。
- 手机号保留 11 位文本，Excel 先把列设为「文本」，防止变成科学计数法。
- 省市区用标准行政区划，例如「北京市 / 北京市 / 朝阳区」，不要写「北京朝阳」。
- 不要合并单元格、不要隐藏列、不要在表头加星号或空格。

### 4.3 模板字段

`*` 为导入履约单时的建议必填。已完成历史单另见第 7 章。

| 列名 | 对应字段 | 必填 | 说明 |
| --- | --- | --- | --- |
| 原始单号 | `tid` / `src_tids` | * | 同一 `sid` 唯一，最长约 40 |
| 原始子单号 | `oid` / `src_oid` | 建议 | 货品行唯一 |
| 店铺名称 | `shop_name` | * | 必须与店铺档案一致 |
| 仓库名称 | `warehouse_name` | 建议 | 不填则走选仓策略 |
| 下单时间 | `trade_time` | * | `yyyy-MM-dd HH:mm:ss` |
| 付款时间 | `pay_time` | 已付款必填 | 未付款填空或 `0000-00-00 00:00:00` |
| 付款状态 | `pay_status` | * | 0 未付款 / 1 部分付款 / 2 已付款 |
| 平台状态 | `trade_status` | * | 常用 `30` 待发货，见附录 A |
| 买家昵称 | `buyer_nick` | 否 | 平台网名 |
| 收件人 | `receiver_name` | * | |
| 手机 | `receiver_mobile` | * | 与固话至少填一项 |
| 固话 | `receiver_telno` | 否 | |
| 省 | `province` | * | |
| 市 | `city` | * | |
| 区 | `district` | * | |
| 详细地址 | `receiver_address` | * | 不要重复拼接省市区 |
| 邮编 | `receiver_zip` | 否 | |
| 商家编码 | `spec_no` / `merchant_no` | * | 必须已在货品档案 |
| 货品名称 | `goods_name` | 否 | 仅展示，不参与匹配 |
| 规格名称 | `spec_name` | 否 | |
| 数量 | `num` | * | 大于 0 |
| 单价 | `price` / `order_price` | * | 货品原价 |
| 优惠金额 | `discount` | 否 | 本行优惠 |
| 邮费 | `post_amount` | 否 | 仅主单第一行 |
| 应收金额 | `receivable` | * | 买家应付合计，仅主单第一行 |
| 物流公司 | `logistics_name` | 否 | 必须与物流档案一致 |
| 买家留言 | `buyer_message` | 否 | |
| 客服备注 | `cs_remark` / `remark` | 否 | |
| 发票类型 | `invoice_type` | 否 | 0 无 / 1 普票 / 2 专票 |
| 发票抬头 | `invoice_title` | 开票时必填 | |

金额勾稽建议：

```
应收金额 ≈ Σ(单价 × 数量 − 行优惠 + 行调整) + 邮费 + 其它费用 − 整单优惠
```

偏差过大会进异常单或财务审核。

## 5. 手工建单

适合单笔或少量线下订单。路径因版本可能是 **销售 → 新增订单** 或 **订单 → 手工建单**。

1. 选择 **店铺**、**仓库**、订单类型（网店销售 / 线下订单 / 现款销售等）。
2. 填写或粘贴原始单号。
3. 把「姓名 手机 省市区详细地址」粘到地址解析框，用空格或中英文分号分隔，点击 **解析**。省市区不规范会解析失败，再手工改。
4. **添加单品** 或 **添加组合装**，按商家编码 / 条码检索，填数量。
5. 维护过售价时，系统会自动算应收。现款已结清、不走财务审核的，按公司规则把应收改为实际收款。
6. 选择物流公司（可稍后在审核界面再选）。
7. 填写买家留言、客服备注、发票信息。
8. 点击 **保存 / 保存为订单**。
9. 到 **销售 → 订单审核** 查找该单，核对后审核。需要走原始单策略的版本，会先出现在原始订单，再递交。

注意：

- 京东等线上店铺不要用来录手工单，改用自有 / 线下店铺。
- 「应用所有行」会按比例重算辅助数量，改数量后如需统一，再点一次。

## 6. 开放接口：原始单推送（履约订单）

用于自研商城、分销、全渠道把 **待发货订单** 推进旗舰版。

| 项 | 内容 |
| --- | --- |
| 推荐接口 | `sales.RawTrade.pushSelf2` |
| 过时接口 | `sales.RawTrade.pushSelf`（不要新用） |
| 客户端查看 | 销售 → 订单管理 → 原始订单 |
| 适用版本 | 客户端 V1.5.9.9 及以上 |
| 店铺限制 | 仅支持自有平台店铺 |
| 单次建议 | 不超过 100 单 |
| 能力 | 新增；也可更新已推送成功的订单 |

上线前必须在测试环境走通：推单 → 原始订单可见 → 递交 → 审核 → 出库。

### 6.1 公共参数

请求发到旗舰版 OpenAPI，`Content-Type: application/json`。时间戳是「当前 Unix 秒 − 1325347200」（即减去 2012-01-01 00:00:00），与服务器误差须在 120 秒内。

| 参数 | 说明 |
| --- | --- |
| `sid` | 卖家账号 |
| `key` | 开放平台 appkey |
| `salt` | appsecret 冒号后半段 |
| `method` | `sales.RawTrade.pushSelf2` |
| `v` | `1.0` |
| `timestamp` | 见上 |
| `sign` | 按开放平台签名算法计算 |

`appsecret` 形如 `testsecret:testsalt`，冒号前为 secret，后为 salt。

### 6.2 业务体结构

请求体为数组，顺序固定：

```text
[ 店铺编号shop_no, [原始单主表...], [原始子单明细...], [优惠明细(可选)] ]
```

主表关键字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `tid` | 是 | 原始单号，同一 sid 唯一 |
| `process_status` | 是 | 线下 / 自有店常用 `10` |
| `trade_status` | 是 | 待发货用 `30`，见附录 A |
| `refund_status` | 是 | `0` 无退款 |
| `pay_status` | 是 | 已付款 `2` |
| `order_count` | 是 | 子单行数，必须等于明细条数 |
| `goods_count` | 是 | 货品件数合计 |
| `receivable` | 是 | 应收合计 |
| `post_amount` | 否 | 邮费 |
| `discount` | 否 | 整单优惠 |
| `trade_time` / `pay_time` | 是 | `yyyy-MM-dd HH:mm:ss` |
| `buyer_nick` | 否 | |
| `receiver_name` | 是 | |
| `receiver_area` | 是 | 如 `北京 北京市 朝阳区` |
| `receiver_address` | 是 | 不含省市区的街道门牌 |
| `receiver_mobile` | 是 | |
| `delivery_term` | 是 | `1` 款到发货 / `2` 货到付款 / `3` 分期 / `4` 挂账 |
| `logistics_type` | 否 | `-1` 表示未指定 |
| `is_auto_wms` | 否 | 非自流转仓不要乱开 |
| `warehouse_no` | 否 | 指定仓库时填写系统仓库编号 |
| `remark` | 否 | 客服备注 |
| `buyer_message` | 否 | 买家留言 |

明细关键字段（`rawTradeOrderList`）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `tid` | 是 | 与主表一致 |
| `oid` | 是 | 子单号 |
| `status` | 是 | 与主单平台状态对齐，待发货 `30` |
| `refund_status` | 是 | `0` |
| `goods_id` / `spec_id` | 建议 | 平台货品 / 规格 ID |
| `goods_no` | 建议 | 货品编码 |
| `spec_no` | 是 | 商家编码，须已存在 |
| `goods_name` / `spec_name` | 建议 | |
| `num` | 是 | 数量 |
| `price` | 是 | 单价 |
| `adjust_amount` | 否 | 调整金额 |
| `discount` | 否 | 行优惠 |
| `share_discount` | 否 | 分摊优惠 |
| `total_amount` | 是 | `price * num + adjust_amount - discount` |

`goods_no` 与 `spec_no` 不能同时为空。匹配以 `spec_no` 为准。

成功响应 `status = 0`，`data.new_count` / `data.chg_count` 表示新增、更新单数。`error_list` 为空表示本批全部成功。示例见 `examples/raw_trade_push_self2.json`。

### 6.3 推单后在客户端做什么

1. **销售 → 订单管理 → 原始订单** 用 `tid` 查询。
2. 状态、金额、货品、地址无误后，右键 **递交**（或开自动递交）。
3. **销售 → 订单审核** 指定仓库、物流，审核。
4. 仓配在 **仓储 → 销售出库 → 销售出库单** 打单、称重、发货。
5. 需要回传物流给商城时，走物流同步接口（`sales.LogisticsSync.*`），与本手册导入流程分开配置。

## 7. 开放接口：已完成订单推送（历史单）

只用于已经发货完成、只需进入旗舰版做对账 / 报表的订单。  
**不会进入待审核发货池。**

| 项 | 内容 |
| --- | --- |
| 接口 | `sales.TradeImport.upload` |
| 客户端查看 | 销售 → 新增订单 → 订单导入（待转已完成） |
| 适用版本 | 客户端 V1.4.7.3 及以上 |
| 权限 | 店铺权限、仓库权限 |
| 批量 | 一次最多 200 条 |
| 更新 | **不支持更新**，单号重复即失败 |

### 7.1 必填字段

业务参数是 `trade_list`。同一系统订单多货品时，多条记录共用 `trade_no`。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `trade_no` | 是 | 系统订单号，最长 40，不可重复 |
| `src_tids` | 否 | 原始单号 |
| `src_oid` | 否 | 原始子单号 |
| `shop_name` | 是 | 店铺名称，精确匹配 |
| `warehouse_name` | 是 | 仓库名称，精确匹配 |
| `logistics_name` | 是 | 物流公司名称 |
| `logistics_no` | 是 | 物流单号 |
| `merchant_no` | 是 | 商家编码 |
| `num` | 是 | 数量 |
| `order_price` | 是 | 货品价格 |
| `receivable` | 是 | 应收金额 |
| `receiver_name` | 是 | 收件人 |
| `receiver_mobile` | 是 | 电话 |
| `receiver_address` | 是 | 详细地址 |
| `trade_type` | 否 | `1` 网店销售 `2` 线下 `3` 换货 `4` 批发 `7` 现款 |
| `trade_from` | 否 | `3` 导入 `5` 接口推送 |
| `trade_time` / `pay_time` / `consign_time` | 建议 | 下单 / 付款 / 发货时间 |

示例见 `examples/trade_import_upload.json`。

成功：`{"status":0,"data":{"message":"OK"}}`。  
常见失败：`订单编号已存在`（`status=100`）。该接口不能改已导入单据，只能换新 `trade_no` 或在客户端作废后处理。

## 8. 导入后标准流转

```text
外部订单
   ├─ 平台抓单 ────────────┐
   ├─ Excel / 接口原始单 ──┤──► 原始订单 ──递交──► 订单审核 ──► 出库打单 ──► 发货
   └─ 手工建单 ────────────┘                      │
                                                   └─ 异常单 / 退款单另处理
已完成历史单 ──► 订单导入（待转已完成）──► 已完成 / 历史订单
```

递交与审核检查：

1. 原始单号未重复。
2. 商家编码已匹配，库存足够（或允许负库存策略已确认）。
3. 地址能解析出省市区，物流可达。
4. 有退款标的先停发。
5. 留言、备注、发票已查看。
6. 仓库、物流与策略一致后再审核。

审核后不可再当「新单」重复导入。要改货、改地址，在订单审核或异常单里处理，或走售后。

## 9. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 店铺编号不存在或已停用 | `shop_no` 填错、店铺停用、非自有平台 | 在店铺档案核对编号与平台类型 |
| 商家编码不存在 / 货品未匹配 | 档案没有该 SKU，或填了货品名称 | 先维护货品档案再导入 |
| 订单编号已存在 | `tid` / `trade_no` 重复 | 原始单用更新接口；已完成单换新单号 |
| 地址解析失败 | 省市区不标准、缺少分隔符 | 用空格或分号，或手选省市区 |
| 手机号变成 `1.38E+10` | Excel 把手机当数字 | 列格式改文本，前面加英文单引号 |
| 乱码 | 编码选错 | 另存 UTF-8，导入时选对应编码 |
| 邮费翻倍 | 多行都填了邮费 | 只在原始单号第一行填 |
| 递交后进异常单 | 缺货、未匹配、地址、黑名单、策略 | 打开异常原因逐项修，再递交 |
| 接口报时间戳非法 | 本地时间不准或时区不是东八区 | NTP 对时，按文档计算 timestamp |
| 推单成功但原始订单没有 | 看错店铺、无店铺权限、查错时间 | 用 `tid` 精确查，核对店铺权限 |
| 已完成单导入后无法发货 | 接口设计如此 | 履约单改走 `pushSelf2` 或手工建单 |
| 平台单与导入单重复发货 | 同一 tid 两处进入 | 平台单禁止再手工导入 |

## 10. 上线检查清单

导入前：

- [ ] 店铺、仓库、物流档案已建且未停用
- [ ] 商家编码已全部维护，组合装已建档
- [ ] 操作账号具备对应店铺 / 仓库权限
- [ ] 已用 1～2 笔测试单在测试环境走通递交、审核、出库
- [ ] 原始单号规则已约定，不会和平台单号冲突
- [ ] Excel 已去掉示例行、合并单元格、公式错误

导入中：

- [ ] 编码、字段映射、预览状态已人工确认
- [ ] 失败行已导出并回修

导入后：

- [ ] 抽样核对收件人、电话、地址、货品、数量、金额
- [ ] 原始订单已递交，异常单已清
- [ ] 需要发货的单已到订单审核，而不是待转已完成
- [ ] 大促前已确认接口单次不超过 100（原始单）或 200（已完成单）

## 附录 A. 平台订单状态

| 值 | 含义 |
| --- | --- |
| 10 | 未确认 |
| 20 | 待尾款 |
| 30 | 待发货 |
| 40 | 部分发货 |
| 50 | 已发货 |
| 60 | 已签收 |
| 70 | 已完成 |
| 80 | 已退款 |
| 90 | 已关闭（付款前取消） |

退款状态：`0` 无退款 / `1` 申请退款 / `2` 部分退款 / `3` 全部退款。  
付款状态：`0` 未付款 / `1` 部分付款 / `2` 已付款。

履约导入请用「已付款 + 待发货 + 无退款」（`pay_status=2, trade_status=30, refund_status=0`），否则可能无法递交发货。
