## 本章目标

1. 理解提示词到底改变了什么——不是「唤醒」了能力，而是改变了输出分布的条件；
2. 从「计算深度」角度理解思维链为什么有效，并用实验量化它的收益；
3. 掌握主要解码策略（贪心 / 温度采样 / top-k / top-p / 集束搜索）的行为差异；
4. 实现自洽投票（Self-Consistency），理解它为什么能救回采样带来的损失，
   以及它的代价是什么。

## 原理

### 提示词做的是条件化，不是魔法

自回归模型算的永远是同一个东西：

$$
p_\theta(y \mid x) = \prod_{t} p_\theta(y_t \mid x, y_{<t})
$$

提示词的全部作用就是改变 $x$，从而改变整个条件分布。所以：

- 提示词**不能**创造模型没有的知识；
- 但它能大幅改变模型「进入哪个模式」，因为预训练语料里不同的表述格式
  对应着完全不同的后续分布。少样本提示的本质是：用几个例子把
  $p_\theta(\cdot \mid x)$ 挪到「按这个格式作答」的那个模式上去。

### 思维链：把串行计算摊进 token 序列

这是本章的核心论点。Transformer 在**单次前向**中的计算深度是固定的
（层数 $L$ 有限），所以有些问题它一步算不出来。但自回归生成给了它一条出路：
把中间结果写成 token，下一步再读回来。

$$
\underbrace{p(a \mid q)}_{\text{固定深度 } L}
\quad\longrightarrow\quad
\underbrace{p(a \mid q, r_1, \dots, r_m)\prod_i p(r_i \mid q, r_{<i})}_{\text{有效深度 } \approx L \times m}
$$

生成的草稿 $r$ 就是**外化的工作记忆**。这解释了为什么思维链对多步算术、
逻辑推理帮助巨大，而对单步事实问答几乎无用——后者本来就不需要串行深度。

本章实验用两位数加法把这件事做成可测量的：

```
直接作答： 80+82=162
思维链  ： 80+82=[0+2=2c0;8+8=6c1]162
                  ↑个位和c进位 ↑十位和c进位
```

两个模型**结构完全相同、题目完全相同、训练轮数完全相同**，
唯一差别是目标序列里有没有那段草稿。

### 自洽投票

思维链 + 温度采样会产生多条不同的推理路径。如果推理错误是**随机**的、
而正确路径是**唯一**的，那么多条路径中正确答案会成为众数：

$$
\hat a = \arg\max_{a} \sum_{i=1}^{k} \mathbb{1}\!\left[\mathrm{extract}(r^{(i)}) = a\right]
$$

关键假设是「殊途同归」：不同的正确推理会到达同一个答案，而不同的错误
会散开到不同答案上。代价是 $k$ 倍推理开销。

## 代码导读

### 提示模板与投票（`dive/prompting.py`）

```python
def zero_shot_prompt(question, instruction=None) -> str
def few_shot_prompt(examples, question, with_reasoning=False, instruction=None) -> str
def chain_of_thought_prompt(question, trigger=COT_TRIGGER) -> str   # 「让我们一步一步地思考。」
def extract_answer(text, pattern=None, last=True) -> str | None      # 默认取最后一个数字
def majority_vote(answers) -> tuple[str | None, int, int]
def self_consistency(sample_once, k=8, extractor=extract_answer) -> SelfConsistencyResult
```

`extract_answer` 默认取**最后一个**数字，这不是随意的选择：
思维链的草稿里全是数字，取第一个必然抽到中间结果。
`tests/test_prompting.py` 固定了负数、小数、无匹配等边界行为。

`self_consistency` 的签名值得注意——它接收一个 `sample_once(i) -> str` 回调，
而不是模型对象。这样同一份实现既能跑本仓库的 TinyLM，也能跑真实 API：

```python
client = OpenAICompatClient(base_url="http://localhost:11434/v1",
                            api_key="ollama", model="qwen2.5:7b")
result = self_consistency(lambda i: client.complete(prompt, temperature=1.0), k=8)
```

`OpenAICompatClient` 只依赖标准库（`urllib` + `json`），所以想把本章实验
搬到真实模型上不需要装任何东西。

### 解码策略（`dive/decoding.py`）

```python
@dataclass
class SamplingConfig:    # temperature / top_k / top_p / repetition_penalty
    is_greedy            # temperature == 0
def top_k_filter(logits, k)  /  top_p_filter(logits, p)
def prepare_distribution(logits, config, generated) -> np.ndarray
def generate(model, prompt_ids, max_new_tokens, config, processors=(), selector=None, ...)
def beam_search(model, prompt_ids, max_new_tokens, beam_size, ...)
```

`generate` 的执行顺序是本章一个容易忽略的细节：

```
logits → processors（水印等） → repetition_penalty → temperature → top_k → top_p → 采样
```

因为温度缩放在 processor **之后**，第 5 章的水印偏置 δ 的有效值其实是 δ/T。
`processors` 与 `selector` 两个钩子让水印（第 5 章）和隐写（第 7 章）
可以复用同一个 `generate`，不必各写一份采样循环。

### 实测结果（800 训练题 / 100 测试题，20 epoch，测试题从未在训练中出现）

#### 实验 A：输出格式的影响

| 输出格式 | 最终训练 loss | 训练用时 | 测试准确率 |
| --- | --- | --- | --- |
| 直接作答 | 0.3153 (ppl 1.37) | 23.0s | 62.0% |
| **思维链** | **0.0263 (ppl 1.03)** | 121.9s | **72.0%** |

思维链带来 **+10.0%** 的绝对提升——模型没变大，只是被允许「把草稿写出来」。

同时注意训练 loss 的差距更夸张（0.32 vs 0.026）：思维链把一个「困难的
多步映射」拆成了若干个「简单的单步映射」，每一步都容易拟合。
**代价写在时间那一列**：目标序列变长了，训练用时从 23s 涨到 122s（5.3 倍）。
这是思维链在真实系统里的核心成本——推理 token 数是要付钱的。

#### 实验 B：解码策略对比（思维链模型）

| 解码策略 | 准确率 |
| --- | --- |
| 贪心 (T=0) | 72.0% |
| 采样 T=0.5 | 72.0% |
| 采样 T=1.0 | 68.0% |
| 集束搜索 (beam=3) | 72.0% |

读法：**对有唯一正确答案的任务，贪心就是最优策略**，采样只会引入噪声
（T=1.0 掉了 4 个点）。集束搜索没有超过贪心——因为这个任务的正确路径
在每一步都是局部最优的，beam 的「暂时保留次优」在这里没有用武之地。

这与「写作类任务需要采样保持多样性」正好相反，是一个必须区分场景的结论。

#### 实验 C：自洽投票（T=1.0，每题采样 5 条推理链）

| 方法 | 准确率 |
| --- | --- |
| 单次采样 (T=1.0) | 62.0% |
| **自洽投票 (k=5)** | **71.0%** |
| 贪心解码（参照） | 72.0% |

一个被投票救回来的真实例子（`74+02=`，正确答案 `076`）：

```
采样：[4+2=6c0;7+0=8c0]086 -> 086
采样：[4+2=6c0;7+0=8c0]086 -> 086
采样：[4+2=6c0;7+0=7c0]076 -> 076   ✓
采样：[4+2=6c0;7+0=7c0]076 -> 076   ✓
采样：[4+2=6c0;7+0=7c0]076 -> 076   ✓
投票结果：076（3/5 票）
```

这个例子把机制展示得很清楚：错误集中在「十位 7+0 算成 8」这一步，
但错误只出现 2 次，正确路径出现 3 次，投票把它救了回来。

**但请注意最后一行**：自洽投票（71.0%）并没有超过贪心（72.0%）。
它只是把采样的损失（62.0%）补回来了，花了 5 倍的推理开销。

这是一个诚实但重要的负面结果。Self-Consistency 论文里投票能超过贪心，
前提是**任务足够难、以至于贪心路径本身经常错**——这时多样性才有价值。
本实验的两位数加法太简单，贪心已经接近这个模型的上限，投票无从改进。
**推论：自洽投票不是无脑增益，它的收益与任务难度正相关。**
第 4 章的三位数加法会给出一个难度足够、思维链收益巨大的对照。

## 思考题

1. 实验 A 里思维链的训练 loss（0.026）远低于直接作答（0.315），
   但准确率只高 10 个点。为什么 loss 的优势没有等比例转化成准确率？
   （提示：一条思维链答案要连续预测对多少个 token？单 token 准确率 99%
   在 12 个 token 上是多少？）
2. 把草稿格式从 `[0+2=2c0;8+8=6c1]` 改成不带进位标记的
   `[2;6]`，准确率会怎样？这说明思维链的收益来自「更长」还是「更好的分解」？
3. 实验 C 的投票没有超过贪心。构造一个任务，使投票**必然**超过贪心。
   你需要控制哪个量？
4. 自洽投票用众数聚合。如果换成「按每条链的平均对数概率加权」会更好吗？
   在什么情况下会更差？（提示：模型对错误答案也可能很自信。）
5. `extract_answer` 取最后一个数字。构造一个会让它抽错的思维链输出。
   真实系统里通常怎么解决这个问题？
6. 集束搜索在本实验没有优势。什么样的任务上 beam 会明显优于贪心？
   为什么开放式生成里 beam 反而会产生重复退化的文本？
